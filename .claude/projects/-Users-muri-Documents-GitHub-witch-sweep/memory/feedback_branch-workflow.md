All work must happen on the `muri/dev` branch. Never commit to `main`.

**Why:** Muri is not a coder and shouldn't have to worry about git. Keeping work on a separate branch protects main and lets changes be reviewed before merging.

**How to apply:** At the start of every session, check you're on `muri/dev`. Commit after every meaningful change — don't batch. Use plain-language commit messages. If on main, switch before touching any files.
